Data: 07/08/2026

O QUE ESTE PATCH FAZ
====================
1. /pages/comecar/ passa a selecionar apenas a ACADEMIA:
   - nome da academia
   - código da academia
   - sem senha de usuário nessa tela

2. Após validar a academia, abre:
   /pages/login/index.html?tenant=<tenant>

3. O login interno pede:
   - e-mail do usuário
   - senha do usuário
   e respeita Administrador, Gerente, Recepção/Operador, Comercial etc.

4. O código FS-XXXX-XXXX passa a pertencer à ACADEMIA, não ao usuário.

5. O login interno exige uma seleção temporária assinada da academia.
   Digitar apenas ?tenant=academia-piloto não basta.

6. Recuperação consolidada:
   - academia + e-mail
   - OTP de 6 dígitos
   - mostra o código da academia
   - opcionalmente redefine a senha
   - volta ao fluxo correto de login

7. /pages/meu-acesso/ passa a mostrar o código DA ACADEMIA.
   Apenas administrador pode regenerá-lo.

TESTE RÁPIDO
============
Se FUSION_RECOVERY_FROM_EMAIL ficar vazio, o código usa:
Fusion Sistema <onboarding@resend.dev>

Atenção: o remetente resend.dev só pode enviar para o e-mail da própria conta
Resend. Para testar cmperuca@gmail.com, a conta Resend de teste precisa estar
associada a esse e-mail.

PRODUÇÃO
========
Depois valide o domínio fusionsistema.com.br no Resend e configure no Render:

FUSION_RECOVERY_FROM_EMAIL=Fusion Sistema <acesso@fusionsistema.com.br>

O render.yaml também prevê:
- FUSION_RECOVERY_SECRET
- FUSION_TENANT_SELECTION_SECRET
com geração automática quando a Blueprint for sincronizada. Se não forem
criados, o código usa o JWT_SECRET existente como fallback.
