Fusion ERP - Regressões P0 V1

Arquivos:
- package.json
- scripts/test-regressoes-p0-fusion.mjs

Instalação:
1. Copie o conteúdo deste ZIP para a raiz do fusion-erp.
2. Escolha substituir package.json quando solicitado.
3. O novo script não altera dados e não chama o Supabase real: o teste de ativação usa fetch simulado e o teste multiempresa usa armazenamento JSON temporário.

Executar apenas a nova suíte:
  npm run test:regressoes-p0

Executar toda a auditoria P0:
  npm run test:p0-auditoria

Cobertura nova:
- contrato de datas civis YYYY-MM-DD;
- mensalidade paga não pode ser próximo vencimento;
- rate limit precisa rodar antes da ativação;
- bloqueio 429 impede o RPC de ativação;
- fluxo permitido chama rate limit e depois ativação;
- instalação inválida falha antes de upstream;
- professor com token do tenant A e header do tenant B recebe 403;
- professor sem header herda tenant do token.

CI adicionada:
- .github/workflows/p0-auditoria.yml
- Em push na main, pull request ou execução manual, o GitHub instala dependências, roda npm run check e npm run test:p0-auditoria.
- A workflow usa apenas permissao de leitura e não recebe segredos.


V2 - Jornada integrada Financeiro + Acesso:
- Novo comando: npm run test:p0-jornada-financeiro-acesso
- Cria aluno/plano em armazenamento temporario.
- Cria matricula pela API real.
- Confirma cobranca inicial e mensalidade inicial.
- Abre caixa e baixa o pagamento.
- Confirma ativacao da matricula e do aluno.
- Confirma recibo e movimento de caixa.
- Confirma programacao da proxima mensalidade sem divida antecipada.
- Simula acesso do aluno.
- Confirma comando de catraca tenant/equipment-aware.
- Simula heartbeat, claim e conclusao do Access Agent.
- Confirma log e presenca.
- Nao usa dados reais e nao chama Supabase de producao.

Depois de copiar:
  npm run test:p0-jornada-financeiro-acesso

Se passar:
  npm run test:p0-auditoria
